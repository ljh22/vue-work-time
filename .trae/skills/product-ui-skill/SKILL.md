# Product & UI Design Skill

> 让 AI 具备产品经理和高级 UI 设计师的视角，生成美观、专业、用户体验优秀的前端代码。

## 激活状态

### ⚡ 默认生效（Always Active）

**此 Skill 默认激活，不需要关键词触发。**

当涉及任何前端界面、组件、页面的开发时，AI 必须自动遵循此 Skill 的规范：

```
任何前端开发任务 → 自动应用产品+UI设计视角
```

### 关键词触发（辅助优化）

仅在以下场景使用关键词辅助定位：
- "优化用户体验" → 深入应用产品设计方法
- "改进 UI" → 深入应用 UI 设计规范
- "设计规范" → 提供设计系统参考

## 核心原则

### 1. 产品经理视角

| 维度 | 要求 |
|------|------|
| **用户价值** | 每个功能都要回答"用户为什么要用？" |
| **信息架构** | 清晰的信息层级，关键信息优先展示 |
| **操作效率** | 减少用户操作步骤，降低认知负担 |
| **容错设计** | 预判错误场景，提供明确的引导和恢复机制 |
| **数据驱动** | 关键操作有反馈，重要数据有可视化 |

### 2. 高级 UI 视角

| 维度 | 要求 |
|------|------|
| **视觉层次** | 通过大小、颜色、间距建立清晰的信息层级 |
| **一致性** | 统一的视觉语言，相似功能相似设计 |
| **响应式** | 适配多端设备，保持核心体验 |
| **可访问性** | 满足 WCAG 标准，考虑色盲/视力障碍用户 |
| **动效设计** | 有意义的动画，增强操作反馈和状态转换 |

## 设计决策框架

### 界面评估清单

```
□ 信息架构是否清晰？
□ 视觉层次是否符合用户阅读习惯？
□ 核心操作路径是否最短？
□ 错误状态是否有清晰提示？
□ 加载状态是否有反馈？
□ 空状态是否有引导？
□ 是否考虑了边界情况（长文本、大数据量）？
□ 是否符合目标用户的心智模型？
□ 动效是否自然流畅？
□ 是否有一致的视觉语言？
```

## 输出标准

### 界面设计标准

1. **结构完整**
   - 清晰的视觉层次（标题 > 正文 > 次要信息）
   - 合理的留白和间距
   - 一致的对齐方式

2. **交互友好**
   - 明确的点击区域（至少 44x44px）
   - 即时的操作反馈
   - 优雅的状态切换动画

3. **视觉精致**
   - 专业的配色方案
   - 细腻的阴影和圆角
   - 清晰的图标风格

4. **响应适配**
   - 移动端优先的响应式设计
   - 流畅的断点过渡
   - 合理的隐藏/展示策略

### 代码质量标准

1. **组件化**
   - 高内聚低耦合
   - 单一职责
   - 可复用可扩展

2. **可维护**
   - 语义化的命名
   - 清晰的代码结构
   - 完善的 TypeScript 类型

3. **性能优化**
   - 懒加载非首屏内容
   - 合理的虚拟滚动
   - 动画使用 transform/opacity

## 项目结构规范

### Vue 项目结构

本项目前端使用 Vue 3 + TypeScript + Vite + Element Plus，完整结构规范参考 `vue-backend/README.md`。

**目录分级原则**：
- **一级目录**：按功能类型划分（api、components、views、stores 等）
- **二级目录**：按业务模块划分（auth、user、product 等）

**禁止混放**：同一功能代码必须放在对应目录下，组件必须按模块划分到子目录。

### 组件分类

| 目录 | 说明 | 组件归属 |
|------|------|---------|
| `common/` | 基础组件，不涉及业务逻辑 | 所有模块共用 |
| `layout/` | 页面结构组件 | 所有模块共用 |
| `auth/` | 登录/注册相关 | 认证模块专用 |
| `user/` | 用户管理相关 | 用户模块专用 |
| `product/` | 商品管理相关 | 商品模块专用 |
