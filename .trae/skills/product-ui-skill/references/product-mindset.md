# 产品经理思维指南

> 以产品经理的视角审视需求，设计有价值、易用、高效的界面。

## 核心思维框架

### 用户价值优先

**每个功能都要回答这个问题：用户用这个功能能得到什么？**

```
❌ 错误思维：我需要一个展示商品列表的页面
✅ 正确思维：用户需要一个能快速找到感兴趣商品并下单的页面

核心价值 = 帮助用户做决策 + 降低购买摩擦
```

### 信息优先级排序

**遵循 7±2 原则，同一区域信息不宜超过 7 个**

```
优先级矩阵：
┌─────────────────┬─────────────────┐
│   P0 必要       │   P1 重要       │
│   核心功能/数据  │   辅助信息      │
├─────────────────┼─────────────────┤
│   P2 增强       │   P3 可选       │
│   优化体验      │   次要功能      │
└─────────────────┴─────────────────┘
```

## 需求分析方法

### 1. 用户故事模板

```
作为 [用户角色]，
我希望 [完成某个目标]，
以便 [获得某种价值]。

示例：
作为电商买家，
我希望快速筛选商品，
以便节省购物时间。
```

### 2. 功能优先级框架

#### MoSCoW 法则

| 优先级 | 定义 | 占比 |
|--------|------|------|
| Must have | 必须有，不满足产品不可用 | 60% |
| Should have | 应该有，提升用户体验 | 20% |
| Could have | 可以有，增强产品亮点 | 15% |
| Won't have | 这次不做，后续考虑 | 5% |

#### KANO 模型

| 类型 | 说明 | 用户反应 |
|------|------|----------|
| 必备型需求 | 理所当然的功能 | 不满意 ← 满意 |
| 期望型需求 | 越满足越满意 | 线性增长 |
| 兴奋型需求 | 超预期的惊喜 | 无 → 惊喜 |

### 3. 用户场景分析

```
场景要素：
- 谁（Who）：目标用户是谁
- 什么（What）：用户想做什么
- 为什么（Why）：背后的动机是什么
- 在哪（Where）：使用环境/设备
- 怎么做（How）：用户的操作路径
```

## 界面设计决策

### 信息架构原则

1. **分块处理**：将复杂信息分成易于理解的组块
2. **渐进披露**：先展示核心信息，按需展开详情
3. **导航清晰**：让用户始终知道"我在哪，能去哪"
4. **路径最短**：常用操作一步直达

### 减少认知负担

```
好的设计 → 用户不需要思考
差的设计 → 用户需要学习、记忆、计算

降低认知负担的方法：
1. 使用用户熟悉的概念和词汇
2. 提供默认选项和智能推荐
3. 展示清晰的示例和预览
4. 即时的错误提示和修正建议
```

### 操作效率优化

**Fitts's Law：目标越大、距离越近，越容易点击**

```
效率优化策略：
- 常用操作放首位（BATNA 原则）
- 默认操作高亮显示
- 支持快捷键/手势
- 批量操作替代重复单次
- 智能填充减少输入
```

## 容错与反馈设计

### 错误类型分类

| 错误类型 | 原因 | 解决策略 |
|----------|------|----------|
| 操作错误 | 用户误触 | 增加确认、撤销功能 |
| 输入错误 | 格式/范围不符 | 实时校验、示例提示 |
| 系统错误 | 网络/服务器故障 | 友好提示、自动重试 |
| 逻辑错误 | 用户理解偏差 | 清晰的引导和说明 |

### 反馈设计原则

```
及时性：操作后立即反馈
明确性：告知用户发生了什么
可恢复：提供撤销或修改的途径

反馈形式：
- 成功：绿色 ✓ + 简短文案
- 错误：红色 ✗ + 具体原因
- 警告：橙色 ⚠ + 引导操作
- 加载：骨架屏/进度条/loading
```

## 边界情况处理

### 空状态设计

```
空状态类型：
1. 全新用户：引导创建第一个内容
2. 无数据：说明原因 + 提供行动
3. 搜索无结果：建议调整筛选条件
4. 网络错误：重试按钮 + 离线提示

空状态设计公式：
情感化插图 + 问题说明 + 引导行动
```

### 加载状态设计

```
加载策略选择：
- 骨架屏：内容结构清晰时（推荐）
- 进度条：可以预估时间时
- 按钮loading：单个操作时
- 分步加载：长列表大数据时

加载文案：
- 使用动词：正在加载、正在保存
- 避免模糊：正在处理 ≠ 正在加载配置
```

### 长文本处理

```
策略：
- 截断 + "查看更多"
- 折叠/展开
- 限制行数 + tooltip 展示完整
- 卡片hover显示详情

行数建议：
- 标题：1-2 行
- 正文：3-5 行（可展开）
- 描述：不限（虚拟滚动）
```

### 大数据量展示

```
优化策略：
1. 分页/无限滚动
2. 虚拟滚动（万级数据）
3. 懒加载
4. 聚合/折叠
5. 搜索/筛选前置

表格优化：
- 固定表头
- 横向滚动
- 列排序/筛选
- 行hover高亮
- 批量选择
```

## 数据可视化原则

### 选择正确的图表

| 场景 | 推荐图表 |
|------|----------|
| 趋势变化 | 折线图 |
| 占比对比 | 饼图/环形图/柱状图 |
| 排名比较 | 水平柱状图 |
| 关联关系 | 散点图 |
| 地理分布 | 地图 |
| 多维对比 | 雷达图 |

### 图表设计规范

```
配色原则：
- 系列区分 ≤ 7 个（色相区分）
- 系列 > 7 个（色相 + 形状）
- 避免红绿搭配（色盲友好）
- 保持对比度 ≥ 4.5:1

标注规范：
- 数据标签清晰可读
- 坐标轴标签简洁
- 图例位置合理
- 标题/来源标注完整
```

## 产品设计检查清单

### 功能设计

```
□ 用户能一眼看懂这个功能是什么吗？
□ 核心操作路径是否 ≤ 3 步？
□ 用户遇到问题能自己解决吗？
□ 是否考虑了新手用户和专家用户？
□ 功能是否有明确的边界？
```

### 信息设计

```
□ 最重要的信息是否最突出？
□ 是否有过多的信息需要用户记忆？
□ 相似的内容是否使用了相似的设计？
□ 是否提供了足够的上下文帮助理解？
```

### 交互设计

```
□ 操作是否有即时反馈？
□ 错误信息是否有用？
□ 是否支持常用操作方式（点击、拖拽等）？
□ 是否有足够的帮助和引导？
□ 是否考虑了无障碍访问？
```

## 经典设计案例参考

### 电商列表页设计

```
用户目标：快速找到想要的商品

设计决策：
1. 搜索框置顶 + 筛选器
2. 网格/列表视图切换
3. 排序（销量/价格/新品）
4. 商品卡片：图 > 标题 > 价格 > 操作
5. 无限滚动 + 回到顶部
6. 空状态：搜索建议 + 热门推荐

避免：
- 无筛选的纯列表
- 过多的筛选维度
- 模糊的排序规则
```

### 表单设计

```
用户目标：快速完成信息填写

设计决策：
1. 一步一任务，避免长表单
2. 字段分组，相关字段放一起
3. 实时校验 + 错误位置高亮
4. 默认值/智能建议
5. 键盘适配（手机号/邮箱）
6. 提交前确认 + 提交后反馈

避免：
- 无标签输入框
- 冗长的必填说明
- 提交后才告知错误
```

## 场景化设计思考（重要）

### 设计前的灵魂拷问

```
每次设计界面之前，必须思考以下问题：

1. 这是什么类型的页面？
   ├── 全屏沉浸式（登录、注册、欢迎页）
   ├── 列表浏览式（商品列表、内容列表）
   ├── 表单填写式（注册、编辑、设置）
   ├── 详情查看式（文章详情、商品详情）
   └── 工具操作式（后台管理、编辑器）

2. 用户使用场景是什么？
   ├── 在哪里用？（PC / 移动 / 平板）
   ├── 什么时间用？（白天 / 夜间 / 通勤）
   ├── 什么心情用？（专注 / 随意 / 着急）
   └── 周围环境？（安静 / 嘈杂 / 公开场合）

3. 用户的目标是什么？
   ├── 快速完成任务？（减少步骤）
   ├── 仔细浏览内容？（信息密度）
   └── 偶尔查看？（快速定位）

4. 可能出现什么问题？
   ├── 网络不稳定？（离线支持）
   ├── 输入错误？（实时校验）
   ├── 操作中断？（自动保存）
   └── 遇到困难？（帮助引导）
```

### 页面类型与设计策略

| 页面类型 | 布局策略 | 核心要点 |
|----------|----------|----------|
| **登录/注册** | 全屏居中，禁止滚动 | 沉浸式、品牌感、快速切换 |
| **列表页** | 搜索前置，分页/无限滚动 | 高效浏览、快速定位 |
| **详情页** | 信息分组、锚点导航 | 内容组织、阅读体验 |
| **表单页** | 分步引导、实时反馈 | 减少错误、降低门槛 |
| **搜索页** | 筛选器、排序、热词 | 快速找到、结果预览 |
| **设置页** | 分组、开关、说明 | 清晰易懂、避免误操作 |
| **后台管理** | 侧边导航、表格为主 | 效率优先、信息密度 |

### 登录注册页设计思考

```
❌ 错误的设计思路：
"做一个登录页面，有用户名、密码、登录按钮"

✅ 正确的设计思路：
1. 用户是谁？
   - 已有账号的老用户（快速登录）
   - 没有账号的新用户（引导注册）

2. 使用场景？
   - 专注的桌面环境（可以多信息）
   - 碎片化的移动场景（简化输入）
   - 公共场合（隐藏密码输入）

3. 核心问题？
   - 账号密码记不住？（支持手机号登录）
   - 注册流程太复杂？（支持快捷注册）
   - 忘记密码？（快速找回）

4. 安全感？
   - Logo 和品牌标识
   - 隐私协议链接
   - 第三方登录背书

5. 防止问题？
   - 账号密码错误（友好提示）
   - 频繁登录失败（防暴力破解）
   - 网络错误（重试机制）
```

### 设计后的自我检验

```
设计完成后，必须逐项检查：

□ 布局
   □ 是否填满了可用空间？（min-height: 100vh）
   □ 是否有多余的滚动条？（overflow 处理）
   □ 是否居中对齐？（flex 居中）
   □ 移动端是否正常？（100dvh）

□ 内容
   □ 信息层级是否清晰？（标题 > 正文 > 辅助）
   □ 重要信息是否突出？（大小、颜色、位置）
   □ 是否有不必要的元素？（简化）

□ 交互
   □ 切换是否有动画？（淡入淡出）
   □ 操作是否有反馈？（hover/active/loading）
   □ 错误是否有提示？（实时校验）
   □ 加载是否有状态？（骨架屏）

□ 状态
   □ 默认状态是否正常？
   □ 加载状态是否友好？
   □ 空状态是否有引导？
   □ 错误状态是否有解决方案？
   □ 成功状态是否有反馈？

□ 响应式
   □ 各断点是否正常？
   □ 移动端是否适配？
   □ 键盘弹出是否正常？
```
